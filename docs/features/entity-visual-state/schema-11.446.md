### 11.446 Stored visual-color RGB channel order

*Status: native graphics-consumer binding, stored-channel decoder projection and retained replay; high byte unresolved.*

The visual-property color word at runtime **+08** stores **red in bits 0–7, green in bits 8–15 and blue in bits 16–23**. This channel order is bound to an actual consumer of `moEntVisProp_c`, rather than inferred from unrelated color helpers. Native `getColor` (`0x4C160850`) projects the word through `0x00FFFFFF` when the layer number is present. `moComponentPropertyHolder::getLineStyleAndWeight` (`0x4B88E320`) passes that output to its color reference. In `sldrgl4u.dll`, call `0x18008A7B2` receives the color into `[rbp-0x50]`; the ordinary visible layer path supplies it unchanged in EDX to the imported `gfxSgColor_c(unsigned long)` constructor at call `0x18008A813`.

The constructor (`sldgfxu.dll`, `0x33AE2620`) extracts the low, middle and third bytes, scales each by the retained float representation of **1/255**, and writes runtime float slots +00, +04 and +08. Exact exported `red()`, `green()` and `blue()` accessors return those respective slots. The full constructor range includes both its ordinary path and its separate all-one input branch. Renderer visibility, layer/default choices and special-color substitutions remain native runtime behavior; the decoder does not simulate them.

`dl_light.read_moEntVisProp_c` now exposes **`color_rgb`** as the tuple `(red, green, blue)` of stored byte values and **`color_unresolved_high_byte`** as the original bits 24–31. `color_word` and its historical alias `unknown_8` remain the complete unmodified u32. `color_is_missing` still recognizes only the exact **0xFFFFFFFF** stored sentinel; an RGB tuple of `(255,255,255)` alone does not imply missing color. For missing color or an absent layer, the tuple is still a raw stored projection, not a resolved display color.

The high byte is discarded by the getter before this graphics path. It is therefore **not established as alpha or reserved**. The full color word retains its four-byte unknown charge under the existing whole-field accounting policy. The ByLayer word and stored state byte also remain partial. No semantic byte gain is claimed: **16,143,727 decoded unknown bytes** remain in the retained part scope, including **894,411 bytes** charged to 127,773 visual records. Historical global coverage checkpoints are unchanged.
