### 14.91 Composer XML-to-geode identifier bindings and local reference index

*Status: Native XML/GUID relationship and complete installed local equality index verified; runtime resolution and full XML value schema remain incomplete · Evidence: C-467*

This connects the binary user-data GUID in 14.87/14.90 with XML `IdentGeom`. It does not equate actor `Ident` with the geometry identifier: repeated actor identifiers and repeated geometry references must remain separate occurrences.

Native `CLitSGToXML::AddGeometryToXMLDoc` at **0x180115800** in **litfoundations.dll**, SHA-256 **757d047481a6a2d31bf44179c140a0d7a8b3b90d619e291cba492da5d10c6bbf**, calls `CLitUserData::GetGuid`, constructs the `IdentGeom` attribute, and calls `SetGuid` with the chosen identifier. Its identifier-selection branch can create a GUID when the existing text is empty or equals the literal `-1`. With a nonempty external-reference prefix, it constructs **`Ref:Ext:` + prefix + `#` + GUID** for the XML attribute, while the user-data GUID receives the unqualified identifier. This explains why stripping or normalizing arbitrary stored text is not a general reference resolver. This writer branch is native evidence, not a claim that every historical file used this installed writer.

`CLitActorFactory::Build` at **0x18038FF90** reads `IdentGeom` through `CLitXmlParserNode::GetAttributeValue`, separately reads actor `Ident`, and passes the geometry reference to **`GetGeode` at 0x1803916B0**. The latter handles external-reference strings, load context, path resolution, merged-file identifiers and global-server lookup. **`CloneGeodeAndAddToSceneGraph` at 0x180391460** supplies actor-instance geometry after lookup. Consequently multiple XML occurrences matching one binary GUID are not duplicate serialized geodes. These ranges are in **litkernel.dll**, SHA-256 **8e7da068cec6f4ac166639d55c1739334221c6964588355b3796334b077487e5**.

Failure handling depends on the actor factory. The mesh factory can retain an unresolved reference, while `CLitActorCurveWireFactory::Build` at **0x18038F990** returns false on its attempted lookup's null result. `CLitRedlineFactory::Build` at **0x1803A7BA0** has a branch that reads `CLitDrawPolyline` and creates a geode from the resulting drawable; a different branch calls `GetGeode`. An unmatched local identifier alone therefore does not prove document corruption or a missing required binary record. The full runtime branch selection and all external resolution fallbacks are not reproduced here.
