### 14.20 Inspection relationship map equality and duplicate insertion

*Status: B / ? — selected native map insertion/equality and original tutorial records verified; caller DOM parsing policy, map iteration order, graph meaning and full project semantics remain partial.*

Following the reader in 14.19, helper `0x1407C6BF0` calls `0x1407C6900`, which calls `0x1407C4B20`. The latter searches through `0x14073F8B0` and tests the candidate through `0x140740AD0`. Both use comparator `0x140090130`, which returns whether `0x14008A670` produces a negative result. Accessor `0x140740930` returns its input pointer unchanged, selecting the key at node offset `+0x20`. These are runtime container offsets, not file offsets.

The complete 103-byte leaf at `0x14008A670..0x14008A6D7` compares the two stored lengths and unsigned 16-bit code units. It first compares the common-length prefix, returning -1 or +1 for the first unequal code unit; if that prefix is equal, it compares the lengths and returns -1, 0 or +1. The string capacity chooses inline versus allocated storage. There is no case folding, locale collation, Unicode normalization, trimming or stop at a zero code unit in this comparator. Two keys are equivalent exactly when their UTF-16 code-unit sequences and lengths agree. A non-BMP scalar and its explicit surrogate-pair representation therefore denote the same native key; Python code-point equality alone is insufficient for a reconstruction that accepts both representations.

`0x14073F8B0` finds the lower-bound candidate; `0x140740AD0` distinguishes a live equivalent node from the sentinel or a greater key. When an equivalent node exists, `0x1407C4B20` returns that node with a false insertion flag. This branch does not assign, append or merge the incoming value vector. Only the other branch allocates and links a new node. Consequently the first equivalent key inserted into the selected map wins. This applies after the reader's text trimming: `<string> A </string>` and `<string>A</string>` collide. A pre-existing map entry also survives this insertion path; the helper does not clear the map. The standalone reconstruction models an initially empty map explicitly.

Repeated `key` children within one outer entry are a different operation: they replace the temporary key, while repeated `value` children append to the temporary vector before its single insertion. Repeated outer entries then compete under first-insertion semantics. Retained outer non-element nodes can insert an empty key and empty vector before a later explicit empty-key entry. The native writer subsequently skips the empty key as specified in 14.19. These operations cannot be reconstructed by choosing the last XML entry or by merging duplicate outer vectors.

It retains source nodes in the attempt view and preserves value order. Output entries retain first-occurrence order for inspection; native map iteration order is not claimed. No parser is selected by these helpers: a DOM that retains whitespace text nodes can produce additional empty-key attempts.
