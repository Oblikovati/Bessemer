# Standalone version histories

`bessemer::history` implements `_MO_VERSION_<n>/History` as documented in
[clause 11.7](specification-11.7.md). This is history behavior version 1. The module
reads a complete archive, constructs new archives from typed values, and edits
owned graphs through `with_contents`. It retains the root class schema, every
stamp field, raw date-code flags, shared date-code object identities, and all
specified tail fields. Unknown enum domains and field meanings remain uninterpreted.

Each state's stored `file_version` selects its date-code branch. The last state's
version selects the tail; neither choice uses the stream name. Validation rejects
empty state/date-code collections, dangling references, orphan date-code objects,
inconsistent version branches or tails, invalid object-map kinds, malformed text,
out-of-bounds lengths, and trailing bytes. Failure returns no partial history.

The archive primitives used here support Latin-1 and UTF-16LE CStrings, retained
length-prefix widths, and short or extended object/class tags. Narrow length
65,534 uses a dword prefix so it cannot collide with the wide-string marker.
UTF-16 counts code units, including surrogate pairs. Ill-formed UTF-16 is rejected,
not replaced with lossy text. Class schemas remain separate from file versions.

`VersionHistory` exposes immutable contents. Callers clone `HistoryContents`, edit
the owned values, and submit the whole graph for validation. New date-code IDs
identify objects within that graph; serialization assigns wire indices in state
traversal order. Equal objects with distinct IDs remain distinct. Shared IDs remain
shared even when states are inserted, removed, or reordered.

No-op saves, equivalent edits, and reverts return the original bytes. Text equality
uses its content and character encoding, so reconstructing the same comment does
not force a private length-prefix normalization. Actual edits rebuild the known
archive and retain untouched CString prefix widths and raw field values. Object
and class tags may use a shorter valid representation after a rebuild.

## Usage

```rust
use bessemer::history::{ArchiveString, TextEncoding, VersionHistory};

let source = VersionHistory::from_bytes(&history_bytes)?;
let mut contents = source.contents().clone();
contents.states[0].stamp.comment = ArchiveString::new("Reviewed", TextEncoding::Utf16)?;
let edited = source.with_contents(contents)?;
let output = edited.to_bytes()?;
```

`cargo run --example set_history_comment -- part.sldprt _MO_VERSION_19000/History
"Reviewed" edited.sldprt` demonstrates the complete document operation. It reads
the named history, changes the first stamp comment, and writes the document while
keeping other streams' compressed bytes. `rebuild_histories` accepts raw-stream
`INPUT OUTPUT` pairs and forces reconstruction from typed values rather than using
the original byte buffer.

## Verification

The owned fixtures include native histories from all three blank documents,
eleven independently assembled version-boundary cases, and a mixed history with
legacy dates, nonminimal string lengths, shared references, and extended tags.
Their expected semantic rows came from the Python reference reader. The native
history encoder reproduces all three fixtures byte for byte without relying on
the original-buffer path.

Integration tests cover every version threshold, every truncation of the native
and mixed streams, generated byte mutations, invalid counts and map kinds, shared
and distinct objects, structural graph edits, CString boundaries, and state/tail
validation. A generated graph crosses both the 32-bit class-tag and object-tag
boundaries. Compile-time Send/Sync assertions cover every public type; eight
concurrent edits produce identical output without changing the source. Input-byte
mutation and failed edits also leave published input histories unchanged.

On Windows x64, an independent Python check extracted all 1,115 installed core
document histories, covering 54,323 states and 58,043 date-code words. The Rust
example rebuilt them from typed values. The reference reader verified every stored
value, class schema, and shared-object relationship in the output. All 1,115
rebuilt streams were also byte-identical to their sources. The ordered corpus
manifest SHA-256 was
`e58a149aff1d499afcf9f62ee48289292e6c4c3fe0ca4f5e1425c075a5b771bb`.
Its input was each sorted sample's relative path with `/` separators, a zero byte,
the stream name, a zero byte, and the raw history bytes, concatenated in order.

The reference also checked whole-document comment edits on the three owned native
documents: the changed text matched, every other history field stayed unchanged,
and every other stream retained its exact compressed payload. Separate Rust
processes produced identical edited documents. Separate-process rebuilds of all
15 owned history vectors also matched. Temporary outputs were discarded.

`cargo xtask pr` passed locally with 54 integration tests and 25 documentation
examples and three xtask unit tests. Cross-platform gates are recorded by the
feature PR. Its Linux full check also runs `cargo xtask tsan`, using
`nightly-2026-10-23` with `rust-src` and a separate `target/thread-sanitizer` directory.
The gate instruments Bessemer, dependencies, and the rebuilt standard library,
following the [Rust sanitizer instructions](https://doc.rust-lang.org/unstable-book/compiler-flags/sanitizer.html#threadsanitizer).
Install that nightly and component before running the gate locally on Linux x86_64.
No dependency was added. This checks archive validity and preservation; native
SolidWorks application acceptance and performance benchmarks remain unexecuted. There
is no earlier Bessemer release for a release-to-release benchmark. Database-archive
history variants are outside the documented standalone layout and remain unsupported.
