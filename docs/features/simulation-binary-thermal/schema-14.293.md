### 14.293 Pressure optional point-pair bodies and terminal table records

*Status: constructor-bound nested layouts recovered statically; populated native boundary validation remains open · Evidence: C-669*

**Optional dispatch binding.** The complete-object vtable **0x181F5F960** installed by 14.291's Pressure constructor has slot **+0x48 → 0x180B78D60–0x180B78F06** (write) and **+0x50 → 0x180B72100–0x180B7230B** (read). These are the optional-body calls in 14.292, relative to the complete object rather than its **+0x08** serializer subobject. C-669 verifies both raw slot pointers and retains all nested function-span/instruction and decompilation hashes against the installed module.

**Optional body grammar.** After a nonzero presence value in the parent, the read helper consumes a persisted CString, then **five four-byte integers**. Call these integers A–E in wire order; their domain meanings are not established. Integer **B** selects a special branch: when **B == 4**, exactly **nine doubles / 72 bytes** follow. At supplied version **>= 820011**, one further four-byte integer follows; older reads initialize its runtime destination to zero without consuming it. If integer **E** is positive, consume **E pairs of doubles**, two eight-byte values per iteration. The memory array stores first values and second values in separate halves, but the **wire order is interleaved pairs**. A bounded parser must check E and **16 × E** against limits/available input before allocating or iterating.

The current write helper obtains the name/header information through the optional object's virtual interface, emits the same name and five integers, emits nine doubles for **B == 4**, then **always** writes the extra integer and paired values. Pair emission requires both positive E and a nonnull runtime data pointer. This does not prove malformed object states produce a complete stream, or that current emission reproduces old versions. The read helper allocates **0x120-byte** objects through constructor **0x180FFA410**; allocation size and runtime setters are not additional wire bytes. C-669 reads gate constant **0x181F61F88 = 820011** directly from the PE. The parent has two independent optional-body locations, each governed by its own presence value.

**Terminal record grammar.** The direct helper **0x180D59E50–0x180D59EFE** uses persist-stream mode to select write/read. Each record consists of **one persisted CString**, followed by exactly **15 interleaved pairs of one double and one four-byte integer**. Thus the fixed portion after the complete string frame is **180 bytes**, with no record-local count or version gate in this helper. On read, doubles populate record **+0x08 + 8i**, integers populate **+0x80 + 4i**, and the CString goes to **+0xC0**, for **i = 0..14**. These are record-relative destinations, independent of the parent subobject offsets. Preserve raw double bits and integer words; no labels or units are assigned here.

Constructor **0x180D49150–0x180D49212** installs its vtable, initializes the CString and clears those numeric storage regions. Those initialization operations add no wire fields. The **200-byte** runtime record allocated in 14.292 is therefore distinct from its variable-length persisted representation. The parent supplies a separate count and applies the already documented mode/range/count clamp; that clamp must not be mistaken for record-local framing or a rule to discard unknown extra bytes safely.

No optional/table native payload has yet been completely parsed using these layouts. C-669 establishes static dispatch and nested grammar, not domain semantics, full Pressure framing, native round trips or storage-path selection. Populated reference-container archives remain a separate dependency. No target execution or global semantic byte credit occurs.
