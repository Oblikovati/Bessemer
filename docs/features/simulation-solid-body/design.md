# Solid-body operation boundary

One direct body starts with two persist-ID words and a bounded byte blob. From
840002 it contains two embedded archives, each with its own stored inner version.
Three counted texts surround four words before the historical suffix fields.
Preserve the physical order of the 830029 mixed word/double block, the earlier
810029 helper that follows it, the late signed fields, list128 and final texts.
Do not sort fields by destination offset or threshold value.

Reuse existing embedded representation readers and their version constraints.
C-734 binds SimpleEdge, CopySurf, MacroFeatRefSurf and EndCapChamfer suffixes;
these identities already have production representation support. Prove their
complete operation in this archive context before extending any dispatch. Never
lower a general minimum version or alias a class merely to consume bytes.

The initial behavior must preserve all earlier C-731 successful bytes and every
C-734 accepted/failed version alternative. Version normalization happens once;
runtime study selection remains a separate question. Exact standalone EOF,
explicit aggregate/embedded budgets and independently derived complete field
and nested edit/history projections gate publication.

Expose immutable, isolated results through existing archive, edit and identity
infrastructure. Keep body framing acceptance separate from physical/native
application and geometric acceptance. A complete solid-body Property does not
establish complete manager/storage-tree support or resolve the six documented
SurfaceBody trailer cases.
