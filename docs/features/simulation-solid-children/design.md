# Component and folder header boundaries

Use an explicit component/folder body kind and normalized historical version.
A component body starts with text68, then words 70/74/78, gated 7C and gated C0.
A folder body starts with word58/text60 and a counted list, followed by gated
A0/AC words. No collection or persist-ID prefix belongs to either direct body.
Sibling Component PersistID and nested body streams are separate operations.

Reuse the shared outer-only limit mapping and exact scalar/text construction,
revision identity, isolation and ordered history infrastructure. Aggregate entry
budgets apply to the folder list; component headers declare no list entries.
The folder clause establishes a signed count but no recovered fixed numeric
upper cap. Bound it by its natural signed wire range, remaining complete text
headers and explicit caller budgets. Do not copy the direct manager's unrelated
100000 hard cap into this grammar without evidence.

The initial independent folder behavior is profile 1: negative counts fail
explicitly, following the clause's safe bounded-reader policy. The native loop
skips nonpositive counts; no native folder fixture validates that runtime case.
Record this scope rather than claiming native behavioral equivalence. Any later
policy change needs an explicit behavior decision and replay migration.

Static folder field vectors are literal encodings and expectations derived from
the frozen clause, independently bound reader function/decompilation and slot.
They are not outputs from an invented Python folder parser. Shared counted-text
frames are checked with the unchanged actual text reader. Native replay covers
only component Property and preserves all accepted/failed argument alternatives.
The zero retained folder-stream denominator does not exclude empty storages or
unrepresented files.

Before publication require complete field and edit/history expectations, owned
degenerate/raw/duplicate profiles, exact and one-below resource budgets,
truncation/count failures, source isolation, Send/Sync/concurrency, fresh-process
exports and full local/platform gates. Preserve raw frames and signed bits;
field meanings, runtime repairs, native writer/application and geometric
acceptance remain separate.
