# Component-reference curves

Bessemer reads, edits and writes `moCompReferenceCurve_c` in ordinary non-DB
external-XML part archives newer than `0x27CB`. Specification 11.185 / C-213
binds its primary serializer to the existing complete component-feature helper.
There is no derived suffix. The supplied native evidence is retained with its
source hash, and its installed-module hash was verified.

The shared component-reference base retains its independent version gates,
component pointer, metadata, optional strings and transform. A signed feature
ID and an unsigned feature time follow it. No additional base or object-map
slot is introduced by reusing the helper. Native `moCompRef_c` ancestry admits
the concrete class through existing reference-wrapper pointers; sharing a
serializer does not expand unrelated component-feature pointer families.

The independent reference reader consumed 198 complete graphs through exact
EOF, producing 11,961 primitive observations. Eleven versions cover both sides
of each inherited base transition and the maximum stored version. Fixtures
cover standalone objects, fresh wrappers and cached wrapper targets, null and
complete shared unit components, populated optional inherited fields, signed
ID extrema and unsigned times including `0xffffffff`. Equal records retain
distinct identities, and repeated occurrences remain aliases. Eight owned
streams begin with the actual document-derived map of 97 slots; two are
independent one-ID edit goldens.

every prefix and extra byte, enforce the old-context boundary, reject an
unrelated cached object in the wrapper role, and check the 90-byte latest
null-component body. Three public tests reconstruct all containing documents,
match isolated ID edits to independent goldens, preserve the second equal
record and shared targets, and verify input isolation after source mutation
or a rejected field-type edit. Two Python tests regenerate all fixtures.

Native geometry resolution, feature ID/time domains, old or special archive
contexts, application acceptance and full documented-schema parity remain
unproven. No dependency, exported Rust API, runtime function or package version
changed. The humanizer skill is unavailable; its prose pass remains with the
maintainer.
