# Model node stored flags, behavior profile 1

`model-node-stored-flags-v1` adds named projections and selected-bit edits over
complete existing part configuration and resolved-feature archives. It changes
no persisted layout, accepted version boundary, field path or previous general
field-edit behavior. There was no earlier public named node-flag API to migrate.
Existing raw access and operations remain available for replay.

The view requires a revision-bound signed node state field and its exact
adjacent flags/ID shape. Parameter-only roles additionally require a direct
owning definition from the finite approved class set. Loaded-class definitions
retain their resolved class; aliases do not manufacture new node fields.
Absence of the second word remains distinct from zero.

Edits set or clear exactly one documented stored bit, preserving all other bits
and reusing complete archive validation and structural history. They do not
simulate native setter cascades, virtual predicates, pointer allocation,
reference-count decisions or equation evaluation. Unexplained bits remain raw;
no whole-word semantic or geometric validity is claimed.

Independent owned literals and original reader spans establish expected bytes
and roles. The previous owned packet and oracles remain byte-identical to
commit676e7257f298a7d078a11ae3a30f1e28a9b258df. The complete original906-case
private/public reconstruction gate passes, and native views retain the original
39,487 parameter denominator. The [operation ledger](operation-verification.json)
records executed checks and exclusions. Repository/publication gates, broader
schema parity and application/geometry acceptance remain pending.
