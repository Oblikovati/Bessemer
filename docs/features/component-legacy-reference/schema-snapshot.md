### 11.454 Direct legacy component-reference payload

*Status: exact concrete serializer and time-width binding; nonzero direct-payload support, stored-presence decoding and retained replay.*

The component-reference word at runtime **+84** is the signed **legacy-reference presence** value. Base serializer `moCompRef_c::Serialize` reads it at outer versions greater than **0xD9A**, already satisfied in the common reader's supported context. Every **nonzero** value selects one direct **moOldRef_c** payload at runtime +88. It is a presence value, not an array count; its magnitude does not change the number of records.

Native loading allocates a 0x18-byte runtime object, installs its concrete vtable and invokes virtual serializer slot +28 directly. **[C-1983]** binds that slot by RTTI to **0x4C1A8370**. The direct serializer stores/loads exactly two entries, in order:

| Entry | Runtime member | Wire representation | Decoder field |
|---|---|---|---|
| 1 | +08 | Ordinary tagged generic `CObject` pointer; null, existing reference or fresh supported object. | `legacy_reference.object` |
| 2 | +10 | One **four-byte** `su_CTime` archive value, retained as raw u32. | `legacy_reference.time_word` |

The second entry is **not another object pointer**. Exact import symbols distinguish the generic object-pointer archive operators from the `su_CTime` operators. The installed `swccu.dll` time loader and its unsigned-word reader independently prove the four-byte cursor advance. Native loading can expand the time into an eight-byte runtime value and handle the all-one sentinel specially; the decoder preserves its original four unsigned bytes without epoch, unit or sentinel conversion.

The 0x18-byte runtime allocation does **not** imply a 24-byte wire body. With a null or short existing object reference, the direct body is six bytes. A fresh object's class declaration and body have their normal variable wire length. The **moOldRef_c wrapper has no enclosing object tag, class declaration or map slot** at this location. Only its contained object pointer participates in the ordinary inherited MFC map.

`modelcomponents.component_reference` exposes **`has_legacy_reference`**, preserving `unknown_84` as an equal signed raw alias. Zero leaves `legacy_reference` absent. A nonzero value invokes the direct helper `legacy_component_reference`, then resumes with the existing missing-state and remaining common-prefix fields. This replaces the former unconditional rejection of nonzero legacy presence. The separate direct component-reference-info branch remains an explicit unsupported case. No speculative global tagged reader for moOldRef_c is registered.

The generic object's purpose and the time word's interpretation remain partial, so the direct helper conservatively charges both entries as unknown. Their pointer identity, nested decoded values and complete raw time bits are still preserved. Native loading resets the presence and schedules the temporary wrapper for deletion, and current native saving forces the legacy-presence value to zero. Those runtime cleanup/translation effects are not applied to stored values by this reader.
