## Embedded-part reader development

The tool wrapper now selects the inline part reader only around its part
pointer. The reader shares the archive map, decodes an inline header and reuses
both established part stages within their declared byte bounds. It restores the
caller's factory selection and completed-part proof after success or failure.
The external part path retains its required unit component; the inline concept
retains the reference reader's nullable component pointer.

Four independent fixtures cover a complete embedded blank part, a null part
pointer, two tools sharing one part and an independently edited part name. The complete graph occupies 26,007 bytes
and has 162 map slots. The paired graph occupies 26,036 bytes and has 165 slots;
the second tool reuses the first part's identity. Source observed 16,600
primitive reads across these four graphs. All fixtures regenerated byte for
byte. Ten malformed section counts were rejected by the actual Source reader,
which also restored its caller's reader table.

Nine focused Rust tests compare those primitive partitions, exact bytes and map
counts, reject inexact section ends and wrong cached pointer classes, and check
restoration using a proof issued by a completed external part. Two additional
tests bind the fixed 16-byte raw-field projection. All eighteen existing part
and lightweight tests and workspace Clippy passed. These local checks do not
replace the full PR gate for the new embedded reader.

Variable-length embedded edits derive section sizes from the inner parts outward.
The independent name edit grows the lightweight section by ten bytes while the
resolved section remains unchanged. Tests reject duplicate, missing, reordered
and wrongly typed size fields and verify that tool suffix words stay outside
the part sections. A nested arithmetic case checks the derivation order.

The complete instance reuses the body-feature base and direct keeper. Twenty-six
independent graphs cover versions 11000, 18000 and 19000, concrete and declared
representation callers, compact transform flag branches, suppressed bodies and
attribute lists, nonpositive counts, duplicate map entries and the embedded part.
Their 12,625 primitive observations and four owned feature streams with 12,460
observations regenerated byte for byte. Public API tests reopen both stream
forms, check an independent word golden, and apply and revert a variable-length
embedded name edit. Edit history records the name and derived size changes.

Two independent native processes accepted all 906 configurations with identical
outcomes, adding case 658 without losing an earlier accepted case. Both runs
forced typed reconstruction through the public API with the explicitly supplied
kernel schema. The actual Source reader separately reached exact EOF over all
83,682,596 resolved-feature bytes, with all four input-stream hashes checked per
configuration. `native-corpus.json` and `accepted-reference.json` retain the
results. This completes the selected modern-part corpus; broader part,
assembly, drawing and project-format parity remains open. The full local PR
gate for the complete instance passed 2,783 tests, including 277
doctests; three native tests remained explicitly ignored in that gate.

## Inline-header implementation

The inline reader reuses the standalone header field recipes, version-marker
constant and decimal version parser. It retains original MFC tags and reads
header dependencies on the containing map. A header-body version override is
local to that header; outer suffix fields and the caller retain their original
version after success or failure. Revision stamps use the existing stamp reader.
Generic lists can retain cached caller objects; fresh model dependencies use the
existing model dispatch rather than a second object map.

The committed independent boundary vectors and native part header bind the new
path. Additional vectors cover older direct shared-file strings, an escaped
CString-array count and a next-ID edit whose independent golden changes only
that word. `freeze_inline_headers.py` observes the actual reference primitives,
checks complete byte partitions and map sizes, and regenerates the committed
packet byte for byte from an immutable Source copy. All 28 cases and 2,857
primitive reads passed, along with seven focused Bessemer tests. The full local
PR gate passed 2,765 tests, including 277 doctests; three native tests remain
explicitly ignored in that earlier gate. The inline reader is now also used by
the forming-tool part body.
